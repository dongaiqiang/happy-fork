# 2026-03-26 语音输入 Provider 化迁移清单（不改外部体验）

## 1. 目标

- 目标：把当前语音输入实现收敛为 Provider 架构。
- 约束：不改变现有用户体验（设置项、按钮行为、识别效果保持一致）。
- 原则：低侵入、可回退、便于上游合并。

## 2. 迁移后结构（文件级）

- 新增：`packages/happy-app/sources/features/voice-input/providers/types.ts`
  - 定义统一接口（start / stop / destroy / 事件订阅）
- 新增：`packages/happy-app/sources/features/voice-input/providers/streamingAsrProvider.ts`
  - 承载当前 `useCustomASR` 内的流式 ASR逻辑
- 新增：`packages/happy-app/sources/features/voice-input/providers/elevenlabsProvider.ts`
  - 封装原有 ElevenLabs 触发逻辑（最小封装，不重写底层）
- 新增：`packages/happy-app/sources/features/voice-input/providers/providerFactory.ts`
  - 根据 `voiceInputMode` 返回 provider
- 新增：`packages/happy-app/sources/features/voice-input/useVoiceInputController.ts`
  - 统一按钮层需要的状态与动作（isListening/start/stop/onText）

- 改造：`packages/happy-app/sources/features/custom-asr/useCustomASR.ts`
  - 迁移核心逻辑到 `streamingAsrProvider` 后，这里变为轻壳或废弃（分阶段）
- 改造：`packages/happy-app/sources/features/custom-asr/CustomASRButton.tsx`
  - 只依赖 `useVoiceInputController`，不直接耦合具体语音方案
- 改造：`packages/happy-app/sources/features/custom-asr/SmartVoiceButton.tsx`
  - 只做模式选择，不并行渲染两套入口
- 保持：`packages/happy-app/sources/app/(app)/settings/voice.tsx`
  - 设置项先不变，只驱动 `voiceInputMode`

## 3. 分阶段实施（建议两步）

### Phase 1：纯重构，不改行为

- 抽 `Provider` 接口与 `Factory`
- 当前 `streaming_asr` 行为完全照搬
- `elevenlabs_call` 只做薄封装
- 验收标准：用户无感，行为与当前一致

### Phase 2：清理与归并

- 减少 `custom-asr` 历史路径重复代码
- 统一语音按钮渲染入口
- 补充开发文档与上游 PR 说明

## 4. 验收清单（不改体验）

- [ ] 设置仍显示两种模式（不改文案也可先保留）
- [ ] 输入区同一时刻只有一个语音入口
- [ ] `streaming_asr`：连续出字、停止收口、可发送
- [ ] `elevenlabs_call`：原有流程不回退
- [ ] 切换模式后无需重启页面（或按当前规则生效）
- [ ] `yarn typecheck` 通过

## 5. 回滚策略

- 保留旧路径入口一个版本周期
- 通过 feature flag（或模式开关）可回退到旧实现
- 回滚只需切换 provider factory，不改 UI 层

## 6. 提交上游的建议拆分

- PR1：引入 Provider 抽象（零行为变化）
- PR2：接入 streaming provider（可选开启）
- PR3：文档与配置说明（含排障）

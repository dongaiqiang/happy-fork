## 2. 今天得到的关键结论

- **结论 1：daemon 停止，不等于已有 session 立刻死亡**
  - 已有 session 依然可以通过自己的 session-scoped 连接继续工作，因此“停 daemon 后还能聊天”是符合当前架构的正常现象。

- **结论 2：daemon 是远程控制入口，不是旧会话的唯一生命线**
  - 没有 daemon 时，新 session 无法从 App 端远程创建，这一点已经通过实验验证。

- **结论 3：machine online 与 session online 需要分开理解**
  - machine 状态受服务端超时机制影响，存在延迟掉线窗口；session 是否继续活跃则取决于它自己的保活与运行状态。

- **结论 4：机器列表里的“机器是否存在”与顶部“已连接”不是同一个状态**
  - 当前前端很多机器列表只展示 active 机器，因此 daemon 停止后，machine 可能直接从列表中消失，而不是保留为 offline。
  - 设置页顶部“已连接”表示的是 App 与服务端的全局连接仍在，不等于 daemon 仍在线，也不等于 machine 仍可控。

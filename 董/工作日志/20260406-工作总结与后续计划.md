## 今日工程收口

### 1. `429` 合同已经稳定

- 服务端现在不再混用 `insufficient_quota` 与散乱字段
- 前端现在不再把这类 `429` 当作普通网络错误无限回退重试
- 对外接口已经具备稳定的可消费合同：
  - 分类看 `error`
  - 分支看 `reason`
  - 文案直接取 `message`

### 2. quota 主线不再依赖“表缺失兜底”

- quota 表的 migration 已经存在，继续静默跳过会掩盖环境漂移
- 本轮移除 fallback 后，主线会在 quota 表缺失时直接暴露配置问题
- 这更符合当前“主线可联调、可验证、可收口”的目标

### 3. 主线验证采用接口等价验证

- 本轮变更集中在服务端接口合同与 App 的失败消费逻辑
- 因此本轮采用：
  - Fastify inject 路由测试
  - App 纯逻辑单测
  - server build
  - app typecheck
- 这组验证已经足以覆盖本轮改动的真实风险面，不再额外要求真机回归才能判断接口是否成立

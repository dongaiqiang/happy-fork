### 2.2A 确认 Redis 已启动

如果你现在的 `.env.production` 里配置了 `REDIS_URL=redis://127.0.0.1:6379`，那 Redis 也属于上线前置依赖，不能漏掉。漏掉时的典型现象就是：

- `pm2 list` 里 `happy-api` uptime 很短、restarts 很高
- `pm2 logs happy-api` 里出现 `ECONNREFUSED 127.0.0.1:6379`
- `curl -I https://api.easycode-ai.xyz` 返回 502

阿里云执行：

```bash
sudo yum install -y redis || (sudo apt-get update && sudo apt-get install -y redis-server)
sudo systemctl enable redis || sudo systemctl enable redis-server
sudo systemctl restart redis || sudo systemctl restart redis-server
redis-cli -h 127.0.0.1 -p 6379 ping
ss -lntp | grep 6379 || true
```

## 4. 上线后验证命令版

### 4.0 手机端先确认入口与地址

阿里云部署完成后，手机端有两个完全不同的入口，不能混用：

1. 业务入口：手机浏览器打开 `https://app.easycode-ai.xyz`
2. 开发入口：Expo Development Build 里的 `Enter URL manually`

这次阿里云联调，默认走业务入口，不走 Expo 本地开发入口。

如果手机上看到的是：

- `No development servers found`
- `Enter URL manually`

说明你现在回到了 Expo Development Build 容器，这不是阿里云部署后的登录页。此时不要在这里填 `https://api.easycode-ai.xyz`，因为这个输入框要的是本地 Expo 开发服务地址，例如 `http://你的Mac局域网IP:8081`。

当前这轮正确做法是：

1. 直接用手机浏览器打开 `https://app.easycode-ai.xyz`
2. 在手机页面设置里，把 server 地址改成 `https://api.easycode-ai.xyz`
3. 再继续登录、打开会话、做 Open in Mac 联调

如果手机里点过注销，也优先按上面这套恢复，不要先折回 Expo Dev Client 入口。

### 4.0A 手机浏览器点击步骤

如果手机浏览器里已经打开了 `https://app.easycode-ai.xyz`，并且你看到了欢迎页上的：

- `使用移动应用登录`
- `创建账户`

那就按下面这套顺序操作：

```text
1. 先点右上角服务器图标
2. 进入“服务器配置”
3. 在自定义服务器 URL 里填 https://api.easycode-ai.xyz
4. 点“保存”
5. 返回首页
6. 再决定是恢复旧账号，还是创建新账号
```

恢复旧账号时：

```text
1. 点“使用移动应用登录”
2. 进入二维码页面
3. 如果你有另一台已经登录 Happy 的设备，就用那台设备扫码
4. 如果你保存过 secret key，就点“Restore with Secret Key Instead”后手工粘贴
5. 恢复成功后再进入会话列表
```

新建账号时：

```text
1. 直接点“创建账户”
2. 创建成功后进入会话列表
3. 再继续 Open in Mac 联调
```

注意：

1. `使用移动应用登录` 是恢复已有账号，不是新建账号  
2. `创建账户` 会生成一个新的浏览器账号，不会自动带回旧会话  
3. 如果原生 Happy App 已经注销，且你没有 secret key，也没有另一台已登录设备，那浏览器里不能直接恢复旧账号，只能先新建账号或先找回旧账号凭据

### 4.0B 三个入口的相互关系

```text
手机浏览器 app.easycode-ai.xyz
    ↓ 负责登录账号、看会话、点击 Open in Mac

Mac 终端 happy auth login / daemon
    ↓ 负责把这台 Mac 机器挂到同一个账号下

原生 Happy App / Expo Dev Client
    ↓ 只在扫码恢复账号或本地 Expo 开发时必须参与
```

一定要记住：

1. 手机浏览器里的 `创建账户` 是“创建账号”  
2. Mac 终端里的 `auth login` 是“给 Mac 机器登录到这个账号”  
3. `Open in Mac` 是“把手机里的会话切给这台已经登录的 Mac”  

所以顺序必须是：

```text
1. 手机浏览器先进入一个账号
2. Mac 终端再登录到同一个账号
3. 确认 daemon 在线
4. 手机里点 Open in Mac
```

### 4.0C 终端认证界面怎么选

当 Mac 终端里出现：

```text
How would you like to authenticate?
1. Mobile App
2. Web Browser
```

当前这轮默认选：

```text
2. Web Browser
```

原因：

1. 它会直接在浏览器里完成终端登录  
2. 不要求你另一台手机 App 先保持登录  
3. 和当前阿里云浏览器入口最一致，最不容易绕乱

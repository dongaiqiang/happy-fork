# HV-006 2026-04-08 Trae-Main 账号提档能力收口结论

## 1. 本轮结论

- `HV-006-TRAE-MAIN-01` 本轮按“账号提档能力收口”范围完成
- 最终采用的承接方式是：保留现有 `/admin/upgrade` 作为标准网络入口，同时补一个主线目录内可直接复用的最小脚本入口
- 本轮没有混入管理员 quota 查询、usage 重置和内部管理页，范围保持合格

## 2. 本轮采用的提档承接方式

### 2.1 标准网络入口

- 路径：`POST /admin/upgrade`
- 作用：适用于已配置 `ADMIN_TOKEN` 的环境
- 输入：
  - `accountId` 或 `username`
  - `tier`
  - 可选 `billingPeriod`
  - 可选 `status`
  - 可选 `endDate`
- 鉴权：
  - `x-admin-token`
  - 或 `Authorization: Bearer <ADMIN_TOKEN>`

### 2.2 最小内部入口

- 命令：`yarn workspace happy-server admin:upgrade -- ...`
- 作用：适用于本地主线联调、真机回归、内部排障时快速解除额度阻断
- 说明：脚本与 `/admin/upgrade` 共享同一套底层提档逻辑，避免网络入口和本地入口出现行为漂移

## 3. 本轮做成的具体结果

- 把账号提档逻辑抽成共享模块，减少路由层散落实现
- 让 `accountId` 与 `username` 两种定位方式都进入统一处理路径
- 让 `free` 回落、非免费档 upsert、自动计算 `endDate`、保留已有 `startDate` 等规则进入统一逻辑
- 补出最小脚本入口，使主线目录以后不必继续依赖临时 SQL 才能提档
- 补齐覆盖 `accountId`、`status`、`endDate` 的测试

## 4. 当前验收判断

- “提档后的订阅状态、有效期与 quota 行为是否符合预期”：已通过真实脚本验证链路确认

## 6. 当前风险与阻塞

### 6.1 非阻塞风险

- 如果目标环境没有配置 `ADMIN_TOKEN`，则不能直接走 `/admin/upgrade` 网络入口
- 当前脚本适用于具备仓库与数据库访问权的内部执行环境，不面向普通用户
- 账号定位本身仍需要先知道 `accountId` 或 `username`，后续若要进一步降低运维成本，应在下一张单补查询能力

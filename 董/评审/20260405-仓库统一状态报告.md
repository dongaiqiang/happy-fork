## 2. 待完成事项

### 2.1 创建 HelloVibe 仓库

**位置：** https://github.com/dongaiqiang/hellovibe

**步骤：**
1. 在 GitHub 创建空仓库 `dongaiqiang/hellovibe`

3. 设置仓库描述："轻松开始氛围编程 - AI-powered coding companion"
4. 添加话题标签：`ai`, `coding`, `productivity`, `typescript`

### 2.2 迁移 Git Remote

**方案 A：重命名当前仓库（推荐）**

如果 `happy-fork` 和 `hellovibe` 是同一用户下：
```bash
# 1. 在 GitHub 上 rename happy-fork → hellovibe
# 2. 更新本地 remote
git remote set-url origin https://github.com/dongaiqiang/hellovibe.git

# 3. 验证
git remote -v
# 应该只显示 origin 指向 hellovibe
```

**方案 B：创建新仓库 + 推送**

如果需要保留 `happy-fork` 作为备份：
```bash
# 1. 创建 hellovibe 新仓库
# 2. 添加新 remote
git remote add hellovibe https://github.com/dongaiqiang/hellovibe.git

# 3. 推送所有分支
git push hellovibe main
git push hellovibe --tags

# 4. 切换默认 remote
git remote remove origin
git remote rename hellovibe origin

# 5. 清理废弃 remote
git remote remove soeasywork
git remote remove upstream
```

### 2.3 验证步骤

```bash
# 1. 检查 remote
git remote -v
# 应该只显示：origin https://github.com/dongaiqiang/hellovibe.git

# 2. 检查分支
git branch -a

# 3. 检查 main 分支跟踪
git branch -vv
# 应该显示：main * xxxxxxx [origin/main] ...

# 4. 测试推送
echo "# HelloVibe Test" >> README.md
git add README.md
git commit -m "chore: test push to hellovibe"
git push
# 验证能正常推送到 hellovibe
```

## 4. 迁移风险点

### 4.1 代码丢失风险

**缓解措施：**
1. 迁移前创建本地备份分支
2. 先在 GitHub 创建 hellovibe 仓库再推送
3. 迁移后验证 commit history 完整性

```bash
# 创建备份分支
git checkout -b backup-before-migration
git push origin backup-before-migration
```

### 4.2 协作中断风险

**影响：**
- 现有 CI/CD pipeline 可能需要更新
- EAS Build/Update 配置可能需要调整
- 团队成员需要更新本地 remote

**缓解措施：**
1. 提前通知团队成员迁移计划
2. 在 README.md 中添加迁移公告
3. 更新 CI/CD 配置中的仓库 URL

### 4.3 链接失效风险

**影响：**
- 旧 issue/PR 链接失效
- 文档中的仓库链接失效

**缓解措施：**
1. 在 happy-fork 仓库置顶迁移公告
2. 更新 CLAUDE.md 等文档中的仓库链接
3. 设置 GitHub repository redirect（如可能）

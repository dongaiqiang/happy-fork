# 20260405 包内容瘦身方案

**创建时间：** 2026-04-05  
**优先级：** P0  
**目标：** 将 npm/tgz 包体积从 216MB+ 降至 5MB 以内

---

## 1. 问题分析

### 1.1 当前包内容体积

| 目录 | 大小 | 当前是否打入包 |
|------|------|---------------|
| `dist/` | 1.5M | ✅ 是（必须） |
| `src/` | 1.9M | ❌ 否（`files` 字段未包含） |
| `tools/archives/` | **216M** | ❌ **是（最大问题）** |
| `tools/licenses/` | 1K | ✅ 是 |
| `tools/unpacked/` | 可变 | ❌ 否（`.npmignore` 已排除） |
| `scripts/` | 96K | ✅ 是 |
| `node_modules/` | 26M | ❌ 否（npm 自动处理） |

### 1.2 问题根源

`tools/archives/` 存储了**全平台二进制压缩包**：
- `difftastic-*.tar.gz` × 6 平台 ≈ 110MB
- `ripgrep-*.tar.gz` × 6 平台 ≈ 106MB

这些是**运行时按平台动态解压**用的，不应打入 npm 包。

当前 `.npmignore` 只排除了 `tools/unpacked/`，但**没有排除 `tools/archives/`**。

---

## 2. 解决方案

### 方案 A：排除 archives + 运行时下载（推荐）

**核心思路：** npm 包不包含任何二进制，安装后从 GitHub Releases 下载对应平台。

#### 2.1 修改 `.npmignore`

```
# Exclude all tools binaries - download on install
tools/archives/
tools/unpacked/
```

#### 2.2 修改 `scripts/unpack-tools.cjs`

改为从 GitHub Releases 下载：

```javascript
// 伪代码示例
const PLATFORM_URLS = {
  'darwin-arm64': 'https://github.com/.../difftastic-arm64-darwin.tar.gz',
  'darwin-x64': 'https://github.com/.../difftastic-x64-darwin.tar.gz',
  // ...
};

async function downloadAndExtract(platform) {
  const url = PLATFORM_URLS[platform];
  const response = await fetch(url);
  const buffer = await response.arrayBuffer();
  // 解压到 tools/unpacked/
}
```

#### 2.3 存储二进制的位置

- **选项 A1：** GitHub Releases（推荐）
  - 创建新 repo 或复用现有 repo
  - 每个平台二进制作为 release asset
  - 优点：免费 CDN，版本管理清晰
  
- **选项 A2：** 阿里云 OSS
  - 上传到 `app.hellovibe.com/binaries/`
  - 优点：国内访问快
  - 缺点：需要额外管理

#### 2.4 优缺点

| 优点 | 缺点 |
|------|------|
| 包体积降至 ~2MB | 安装时间略长（需下载） |
| 按需下载，不浪费 | 需要维护下载 URL |
| 新增平台不用发 npm 包 | 离线安装不可用 |

---

### 方案 B：只排除 archives + 保留 unpacked

**核心思路：** npm 包不包含压缩档案，但包含**已解压的当前平台二进制**。

#### 2.1 修改 `.npmignore`

```
# Exclude compressed archives
tools/archives/

# Keep unpacked for current platform only
# tools/unpacked/  <-- 注释掉这行，允许打入包
```

#### 2.2 发布前准备

```bash
# 发布前只解压当前平台
cd packages/happy-cli
node scripts/unpack-tools.cjs

# 确认只包含当前平台二进制
ls -la tools/unpacked/
```

#### 2.3 优缺点

| 优点 | 缺点 |
|------|------|
| 安装快（无需下载） | 包体积仍较大（~40MB） |
| 离线可用 | 每个平台发布需要重新打包 |
| 改动最小 | Windows 用户会下载到 Mac 二进制（需文档说明） |

---

### 方案 C：双 npm 包策略

**核心思路：** 按平台拆分 npm 包。

#### 2.1 包结构

- `hellovibe-cli-darwin-arm64`
- `hellovibe-cli-darwin-x64`
- `hellovibe-cli-linux-arm64`
- `hellovibe-cli-linux-x64`
- `hellovibe-cli-win32-x64`
- `hellovibe-cli-win32-arm64`

#### 2.2 主包

- `hellovibe-cli` 作为 meta 包，根据平台安装对应子包

#### 2.3 优缺点

| 优点 | 缺点 |
|------|------|
| 每个包体积小 | 维护 6 个包，复杂度高 |
| 安装快 | 用户需要知道自己平台 |
| 类似 `@vercel/ncc` 等成功案例 | 不推荐当前采用 |

---

## 3. 推荐方案

**推荐：方案 A（排除 archives + 运行时下载）**

### 理由

1. **包体积最小** — 从 216MB 降至 ~2MB
2. **最可持续** — 新增平台不用重新发 npm 包
3. **行业标准** — Vercel、Netlify 等 CLI 都这么做
4. **成本可控** — GitHub Releases 免费 CDN

### 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 国内下载慢 | 镜像源（阿里云 OSS） |
| 离线不可用 | 文档说明，提供手动下载链接 |
| GitHub 被墙 | 备用下载源（阿里云） |

## 4. 当前最大风险

### 4.1 安装方式未真正验证 🔴

```
当前状态：
✓ npm pack --dry-run 可用
✗ 未真实执行 npm install -g ./xxx.tgz
✗ 未验证安装后 auth/daemon/tmux 可用
```

**影响：** 这是产品交付的核心路径，如果安装后无法使用，产品无法发布。

### 4.2 品牌视觉不统一 🟡

```
当前状态：
✓ 文案已是 HelloVibe
✗ 图标仍是旧 HappyCoder 的 H 视觉
✗ 用户第一眼看到旧品牌印象
```

**影响：** 品牌切换不完整，给用户造成混淆。

### 4.3 仓库多源并行 🟡

```
当前 remote 配置：
origin     → dongaiqiang/happy-fork (当前主用)
soeasywork → dongaiqiang/SoEasyWork (历史)
upstream   → slopus/happy (原始开源)
```

**影响：** 多 remote 并存，容易混乱，需明确唯一主仓库。

## 5. 下周必须完成的 5 件事（发布 blocker）

### 5.1 真实跑通 tgz 安装闭环

**验收标准：**
1. 生成正式 `.tgz` 包
2. 在干净目录中执行 `npm install -g ./xxx.tgz`
3. 安装后 CLI 命令可执行
4. 输出 `happy --version` 有响应

### 5.2 包内容瘦身

**验收标准：**
1. 明确 `files` 白名单
2. 明确 `.npmignore` 黑名单
3. 包体积较当前明显收敛（目标 < 50MB）
4. 不再混入研发内部工具产物

### 5.3 安装包运行链路验证

**验收标准：**
1. `happy auth` 可用
2. `happy daemon start` 可用
3. `happy daemon status` 可用
4. tmux 相关核心能力可用

### 5.4 图标视觉替换

**验收标准：**
1. 采用第一稿方案（concept-a）
2. 替换 7 个资源文件
3. 真机检查桌面图标/通知图标/启动图

### 5.5 仓库统一

**验收标准：**
1. 明确 `dongaiqiang/hellovibe` 为唯一主仓库
2. 更新 Git remote 配置

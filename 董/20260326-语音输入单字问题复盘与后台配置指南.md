# 2026-03-26 语音输入单字问题复盘与后台配置指南

## 一、问题背景

本次语音输入链路目标是：

- 手机端点击语音按钮开始录音
- 实时把语音转文字回填到输入框
- 点击停止后保留文本，并可发送消息

实际遇到的问题是“只能识别出一个字（或第一小段）”，后续识别结果没有持续更新到输入框。

## 二、问题现象（当时）

- 后端日志显示讯飞识别持续返回：
  - `sn:1 apd -> 你`
  - `sn:2 rpl -> 你好`
  - `sn:3 rpl -> ...`
- 前端输入框只显示第一段，后续不更新。
- 前端日志有持续发送音频块，说明录音并未中断。

结论：不是“录音中断”，而是“前端 UI 消费结果链路断了”。

## 三、根因拆解

### 1) 输入区按钮在识别过程中被切组件，导致监听链路断开

- 旧逻辑里，`hasText` 一出现就从 ASR 按钮切回普通发送按钮。
- 切换组件时，自定义 ASR 组件被卸载，后续 `asr_text` 不再回填同一状态链。
- 这就是“只能看到第一段”的关键原因。

- [CustomASRButton.tsx](file:///Users/dongaiqiang/Documents/mycode/codes/00-chanpin/happy-main/packages/happy-app/sources/features/custom-asr/CustomASRButton.tsx)

### 2) socket 事件注册模型是“单 handler 覆盖”，容易互相顶掉

- 旧实现 `messageHandlers: Map<string, handler>`，同一事件后注册会覆盖前注册。
- `asr_text` 在复杂页面下容易被其他监听覆盖，表现为“只触发一次或不稳定”。

- 直接发 `ArrayBuffer` 在 RN + socket.io 场景并不总是稳定。
- 容易出现后端拿到空块/异常格式，从而影响连续识别。

## 四、已落地修复（最终生效）

### 修复 A：输入区在 `streaming_asr` 模式下保持单组件

- `streaming_asr` 模式始终渲染 `CustomASRButton`
- 按钮内部统一处理三态：
  - 识别中：显示 `stop`
  - 有文本：显示 `send`
  - 无文本：显示 `mic`

效果：不再因为 `hasText` 导致 ASR 组件卸载。

### 修复 B：socket 同事件支持多监听（Set）

- `onMessage(event, handler)` 改为 `Map<string, Set<handler>>`
- `onAny` 时遍历触发全部监听
- 每个 handler 外层加 `try/catch`，避免单个回调抛错中断其他回调

效果：`asr_text` 不再被覆盖或中断。

### 修复 C：音频块统一为 `audioBase64` 上送

- 前端把 `Int16Array` 转 `base64` 后发送（附带 `chunkByteLength`）
- 后端统一兼容解析 `audioBase64 / Buffer / ArrayBuffer / Uint8Array`

效果：跨端传输更稳定，减少“只有首段”的随机性。

### 修复 D：`pgs=rpl` 按“整句替换”处理

- 动态修正场景下，`rpl` 语义是替换当前句
- 前端改为直接覆盖当前句，不做旧 `pop/push` 混合策略

效果：输入框文本与讯飞修正结果一致，避免拼接异常。

### 1) 环境变量

后端需要以下 3 个变量，缺任意一个都会报错：

- `IFLYTEK_APPID`
- `IFLYTEK_API_KEY`
- `IFLYTEK_API_SECRET`

若未配置，前端会收到：

- `asr_error: 后端未配置科大讯飞 API 凭证`

### 2) 启动顺序

1. 根目录安装依赖：`yarn install`
2. 启动后端：`packages/happy-server` 下 `yarn dev`
3. 启动前端：`packages/happy-app` 下 `npx expo start --dev-client -c`
4. 真机安装（需要时）：`npx expo run:ios --device --no-install`

### 3) 前端模式开关

## 七、常见故障与排查

### 故障 1：只能出一个字

优先检查：

- 是否仍在 `streaming_asr` 模式
- 输入区是否仍是单按钮/单组件路径
- `apiSocket` 是否为多监听版本

### 故障 2：`asr_start` 发了但没结果

优先检查：

- 后端环境变量是否完整
- 后端是否打印 `成功连接科大讯飞 WebSocket 服务`

### 故障 3：编译或 dev client 报 plugin 错误

优先检查：

- `expo-build-properties` 是否已安装
- 依赖是否执行过 `yarn install`

## 一、付费墙设计原则

### 1.1 付费墙「五步法」

```
┌─────────────────────────────────────────────────────────┐
│  付费墙设计「五步法」                                    │
├─────────────────────────────────────────────────────────┤
│  1. 先给甜头 —— 让用户体验价值                           │
│  2. 适时出现 —— 在「啊哈时刻」后弹出                     │
│  3. 对比强烈 —— 免费 vs 付费价值差异明显                 │
│  4. 降低门槛 —— 首月优惠/分期降低决策难度                │
│  5. 限时紧迫 —— 24 小时限时优惠促决策                    │
└─────────────────────────────────────────────────────────┘
```

### 1.2 付费墙出现时机

| 时机 | 触发条件 | 行业转化率 | 推荐度 |
|------|---------|-----------|--------|
| **注册后立刻** | 新用户首次进入 | 1-3% | ❌ 不推荐 |
| **首次使用时** | 第一次发送消息后 | 5-8% | ⚠️ 一般 |
| **额度用尽时** | 免费 tokens 用完 | 15-25% | ✅ 推荐 |
| **高价值时刻** | 完成一个任务后 | 20-30% | ✅✅ 强烈推荐 |
| **功能限制时** | 想用模式 B 但被限 | 10-15% | ✅ 推荐 |

## 二、付费墙文案设计

### 2.1 场景一：免费额度用尽时

**触发条件：** 用户当日或当月 token 额度已用完

```
┌─────────────────────────────────────────────────────────┐
│  🎉 您今天的编程体验很棒！                                │
│                                                         │
│  您的免费额度已用完（10 万 tokens）                       │
│                                                         │
│  升级到专业版，解锁无限可能：                            │
│  ✅ 模式 B 云端托管（无需本地配置）                       │
│  ✅ 200 万 tokens/月（是免费的 20 倍）                    │
│  ✅ 20GB 云存储（代码随时访问）                          │
│                                                         │
│  🎁 限时优惠：首月仅 ¥9.9（原价 ¥49）                    │
│  ⏰ 优惠倒计时：23:59:59                                │
│                                                         │
│  [立即升级]  [再看看]                                    │
└─────────────────────────────────────────────────────────┘
```

**文案要点：**
- 开头肯定用户体验（"体验很棒"）
- 清晰说明当前状态（"额度已用完"）
- 列出 3 个核心付费价值
- 突出优惠力度（8 折 + 限时）
- 倒计时制造紧迫感

**数据埋点：**
- `paywall_shown`: 付费墙展示
- `paywall_upgrade_clicked`: 点击升级
- `paywall_dismissed`: 关闭付费墙

## 三、付费墙组件设计

### 3.1 组件状态

```typescript
interface PaywallProps {
    scenario: 'quota_exceeded' | 'feature_locked' | 'task_completed' | 'retention' | 'student';
    variant: 'A' | 'B' | 'C';  // A/B 测试变量
    onClose: () => void;
    onUpgrade: () => void;
}
```

### 3.2 视觉设计要点

| 元素 | 设计规范 |
|------|---------|
| 背景色 | 半透明黑色遮罩 (rgba(0,0,0,0.6)) |
| 弹窗圆角 | 16px |
| 主按钮 | 品牌色渐变 (#6366f1 → #8b5cf6) |
| 次按钮 | 灰色边框，透明背景 |
| 倒计时 | 红色高亮，动态刷新 |
| 图标 | 场景相关 emoji 或 Lottie 动画 |

### 3.3 动画效果

```
进入动画：
- 遮罩：fade-in 200ms
- 弹窗：scale 0.9 → 1.0, 200ms ease-out

退出动画：
- 遮罩：fade-out 150ms
- 弹窗：scale 1.0 → 0.95, 150ms ease-in

倒计时：
- 数字变化：pulse 动画
- 最后 1 分钟：红色闪烁警告
```

## 四、A/B 测试方案

### 4.1 测试目标

**主要指标：** 付费转化率（点击升级并完成支付的用户比例）

**次要指标：**
- 付费墙点击率
- 7 日留存率
- 退款率
- 用户满意度（NPS）

### 4.2 测试分组

| 测试组 | 变量 | 流量分配 | 假设 |
|--------|------|---------|------|
| **对照组 A** | 基础文案（额度用尽时） | 20% | 转化率 15% |
| **实验组 B** | 增加限时优惠 | 20% | 转化率 20%+ |
| **实验组 C** | 任务完成后弹出 | 20% | 转化率 25%+ |
| **实验组 D** | 社会认同 + 锚定 | 20% | 转化率 22%+ |
| **实验组 E** | 免费试用 7 天 | 20% | 转化率 28%+ |

### 4.3 测试周期

```
第 1-2 周：收集数据（每组至少 1000 样本）
第 3 周：统计分析，确定优胜组
第 4 周：全量上线优胜方案
```

### 4.4 样本量计算

**统计显著性要求：**
- 置信水平：95%
- 统计功效：80%
- 最小可检测效应：20% 相对提升

**所需样本量：** 每组约 1000-1500 次付费墙展示

### 4.5 数据追踪


## 2. 当前共识

当前已明确以下共识：

1. 产品名先使用 `helloVibe`
2. 产品不只支持 Mac，也支持 Windows
3. 产品既支持本地设备运行，也支持直接使用服务器运行环境
4. 用户本地不一定必须安装执行端，也可以直接连接服务器上的运行环境
5. 产品不应只绑定 Claude Code
6. 产品应支持多种 AI CLI 编码工具，例如：
   - Claude Code
   - Codex
   - OpenCode
   - 后续其他兼容 CLI

因此，helloVibe 不能再被定义成：

- 只用于 Mac 的工具
- 只用于 Claude 的 companion app
- 单纯的手机遥控终端工具

它应该被定义成一个支持多设备、多环境、多种 AI CLI 连续工作的产品。

## 3. 产品定义

## 3.1 一句话定位

helloVibe 是一个让用户更轻松进入氛围编程状态，并在不同设备、不同运行环境、不同 AI CLI 工具之间自然继续工作的产品。

## 3.2 对外介绍版

helloVibe 让用户更轻松地开始氛围编程，并在手机、Mac、Windows 和服务器之间，连续使用 Claude Code、Codex、OpenCode 等智能编码工具继续工作。

## 3.3 更通俗的解释

它首先要传递的，不是“设备怎么切来切去”，而是：

1. 智能编码这件事可以更轻松开始
2. 用户不用先理解太多技术细节就能上手
3. 用户可以把注意力放在想法和产出上，而不是放在环境折腾上

它解决的也不只是“怎么远程打开一个终端”，而是：

1. 用户怎么更快进入编程状态
2. 用户换了设备以后，工作如何继续
3. 用户离开本地电脑以后，工作如何不中断
4. 用户在本地环境与服务器环境之间，如何自然切换
5. 用户在不同 AI 编码工具之间，如何保持一致的工作方式

## 3.4 helloVibe 里 vibe 的含义

这里的 vibe，不只是一个名字风格，更是宣传上要明确打出来的含义：

1. 更轻松的智能编码体验
2. 更容易上手的工作方式
3. 更少技术门槛的开始过程
4. 更自然进入“我现在就开始做”的状态

所以 helloVibe 更接近一句欢迎语：

- 你好，来轻松开始氛围编程
- 你好，让智能编码这件事更顺手一点
- 你好，现在开始进入工作状态

## 4. 产品边界

## 4.1 它是什么

helloVibe 更像是一个连接三类对象的连续工作层：

1. 设备
   - 手机
   - Mac
   - Windows
   - 网页
   - 服务器
2. 运行环境
   - 本地环境
   - 远程服务器环境
3. AI 编码工具
   - Claude Code
   - Codex
   - OpenCode
   - 其他兼容 CLI

## 4.2 它不是什么

helloVibe 当前不应被定义成：

1. 只服务于 Mac 的桌面工具
2. 只服务于 Claude Code 的移动客户端
3. 纯粹的远程终端控制器
4. 像 Replit 一样从零到一包办建站的全栈应用生成平台

---

## 5. 核心价值主张

建议后续官网、介绍页、演示视频、传播文案围绕下面五点展开。

## 5.1 氛围编程，更轻松开始

helloVibe 要先传递一种感觉：智能编码不是一件很硬核、很折腾、很难开始的事，而是可以更轻松上手、更快进入状态。

## 5.2 简单上手

用户不需要先理解终端、执行端、控制权这些概念，也可以明白自己下一步该做什么。

## 5.3 连续工作

用户可以在不同设备之间继续同一个工作，而不是每次重新开始。

## 5.4 环境自由

用户可以在本地运行，也可以直接连接服务器环境运行，本地甚至可以不安装执行端。

## 5.5 工具开放

产品不绑定单一 AI 编码工具，而是支持多种 CLI 协同工作。

## 6. 可参考产品对比

## 6.1 与 Happy Coder 的关系

Happy Coder 当前更偏：

1. 手机控制电脑上的 Claude Code / Codex
2. 以移动 companion 视角切入
3. 上手路径具体，但产品定义相对较窄

helloVibe 与它相比，应进一步扩大定义范围：

1. 不只支持 Mac，也支持 Windows 和服务器环境
2. 不只支持 Claude，也支持多种 AI CLI
3. 不只解决“手机控制电脑”，更解决“工作如何连续”

## 6.2 与 Vicoa 的关系

Vicoa 的公开表达更偏：

1. Anywhere
2. Any Device
3. 多代理
4. 多端接续

这条路和 helloVibe 非常接近，值得借鉴。

helloVibe 可以在此基础上进一步强调：

1. 服务器环境是正式能力，不是补充场景
2. 用户本地可装，也可不装
3. 产品不仅是远程接入，还强调工作流连续性

## 6.3 与 Replit 的关系

Replit 当前更偏：

1. Build apps and sites with AI
2. 从 idea 到 app
3. 设计、开发、部署一体化
4. 全栈 AI 应用构建平台

helloVibe 不应直接复制这套定位，因为当前优势不在“全栈建站平台”，而在：

1. 多设备接续
2. 多环境自由
3. 多工具兼容
4. 让现有 AI 编码工作不中断

对 helloVibe 最值得借鉴的是 Replit 的表达方式：

1. 先讲用户得到什么结果
2. 少讲底层技术实现
3. 少讲复杂 feature 列表
4. 先把“为什么存在”讲明白

## 8. 宣传口径原则

后续宣传材料建议统一遵守以下原则：

1. 先讲结果，不先讲实现
2. 先讲轻松上手和氛围编程，再讲连续工作
3. 先讲设备、环境、工具，不先讲终端、daemon、handoff
4. 先讲用户为什么需要它，不先讲内部架构
5. 允许产品定义比当前实现略高一层，但不能脱离真实能力

# 20260402 需求清单：helloVibe 术语体系与页面文案草案

## 1. 文档目的

本文件只处理用户看得见的产品语言问题：

1. 术语怎么改得更通俗
2. 页面标题、按钮、状态提示怎么写得更像产品
3. 新用户第一次使用时，如何降低理解门槛
4. 如何把当前偏技术化的表达，翻译成用户任务语言

本文件不处理产品宣传定位，不处理官网品牌对外介绍。这些内容单独放到《helloVibe 宣传与定位草案》中。

---

## 2. 当前问题

当前系统在用户语言上存在几类明显问题：

1. 同一个动作在不同入口里名字不一致
2. 一些技术实现词直接暴露给用户
3. 用户不知道当前页面是在“登录账号”“添加设备”还是“切换工作位置”
4. 成功提示和错误提示更像系统播报，不像用户引导
5. 一些命名仍然围绕 Mac / Claude / terminal 展开，无法覆盖 Windows、服务器、多工具场景

这些问题会直接导致：

1. 新用户觉得难理解
2. 自己都容易被绕晕
3. 用户不知道下一步该点什么
4. 产品虽然能用，但不容易被接受

---

## 3. 术语设计原则

后续术语与页面文案建议统一遵守下面几条原则：

1. 动作优先：先写用户要做什么
2. 一事一名：同一个动作尽量只有一个名字
3. 少用技术词：用户界面尽量少出现 daemon、handoff、controller、carrier 等词
4. 先讲结果：状态提示优先告诉用户现在该去哪继续
5. 面向扩展：命名不能只适配 Mac 或 Claude，要能覆盖 Windows、服务器、多种 CLI 工具

---

## 4. 语言框架

后续产品语言建议围绕三个核心对象展开，而不是围绕内部实现展开。

## 4.1 设备

建议用户界面主要使用：

1. 手机
2. 电脑
3. Mac
4. Windows 电脑
5. 服务器

不建议优先使用：

1. 终端
2. 执行端
3. 节点

## 4.2 环境

建议主要使用：

1. 本地环境
2. 服务器环境
3. 这台设备
4. 这台电脑

不建议优先使用：

1. daemon 环境
2. carrier 模式
3. terminal carrier

## 4.3 工具

建议主要使用：

1. 编码工具
2. 当前使用的工具
3. 选择编码工具

具体工具名保持原名：

1. Claude Code
2. Codex
3. OpenCode

不建议优先使用：

1. agent
2. provider
3. backend runner

---

## 5. 核心术语替换建议

下面先列一版最核心的替换方向。

| 当前表达 | 建议表达 | 说明 |
| --- | --- | --- |
| 创建账户 | 新建账号 | 更自然 |
| 登录 | 登录已有账号 | 便于和新建区分 |
| 使用移动应用登录 | 用手机登录 | 更直白 |
| 认证 | 登录验证 | 降低技术感 |
| 连接终端 | 添加设备 | 用户知道自己在加一台设备 |
| 接受连接 | 确认添加 | 更像产品动作 |
| 执行端 | 运行环境 | 更容易理解 |
| 本地执行端 | 本地环境 | 更贴近用户认知 |
| 远程执行端 | 服务器环境 | 直接说人话 |
| agent | 编码工具 | 用户能理解在选什么 |
| session | 对话 | 更通俗 |
| new session | 新建对话 | 一眼明白 |
| resume session | 继续这次对话 | 更自然 |
| Open in Mac | 在这台设备上继续 | 便于覆盖 Windows / 服务器 |
| 当前由 Mac 控制 | 当前请在这台设备上继续 | 少用控制这个词 |
| 手机端只读 | 手机当前可查看，不可输入 | 更像用户提示 |
| handoff | 切到另一台设备继续 | 不显示内部词 |
| daemon 未启动 | 这台设备还没有准备好 | 更友好 |
| session not found | 没找到这次对话 | 更容易理解 |

## 6. 页面草案

## 6.1 登录页

### 页面目标

让用户先理解：

1. 我在登录同一个账号
2. 登录后不同设备才能同步
3. 这一步不是在添加设备，也不是在启动工具

### 推荐标题

- 登录账号

### 推荐副标题

- 先登录同一个账号，这样你的设备和对话才能同步使用

### 推荐按钮

- 新建账号
- 登录已有账号
- 用手机登录

### 推荐补充提示

- 登录后，你可以在手机、电脑和服务器之间继续同一个工作

---

## 6.2 添加设备页

### 页面目标

让用户理解：

1. 我是在把一台设备加入当前账号
2. 后面可以在这台设备上继续工作
3. 不是在“连接终端”这种技术动作

### 推荐标题

- 添加设备

### 推荐副标题

- 把一台电脑或服务器环境加入当前账号，之后就可以在这里继续工作

### 推荐按钮

- 添加这台 Mac
- 添加这台 Windows 电脑
- 连接服务器环境
- 确认添加

### 推荐状态提示

- 这台设备已可用
- 这台设备还没有准备好
- 服务器环境已连接
- 当前设备离线

---

## 6.3 选择编码工具页

### 页面目标

让用户理解：

1. 我现在是在选用哪个编码工具
2. 产品支持多种工具，不只 Claude
3. 选工具和选设备是两件事

### 推荐标题

- 选择编码工具

### 推荐副标题

- 选择这次要使用的工具，例如 Claude Code、Codex 或 OpenCode

### 推荐按钮 / 标签

- Claude Code
- Codex
- OpenCode

### 推荐补充提示

- 不同工具可以运行在本地环境或服务器环境中

---

## 6.4 会话页

### 页面目标

让用户理解：

1. 当前我在处理的是一段对话
2. 我可以在另一台设备或另一种环境里继续
3. 不要把动作理解成“Open in Mac”这种局部场景

### 推荐标题

- 对话

### 推荐动作按钮

- 新建对话
- 继续这次对话
- 在这台设备上继续
- 切到另一台设备继续
- 切到服务器继续

### 推荐状态提示

- 已经在这台设备上打开
- 接下来请在这里继续
- 手机当前可查看，不可输入
- 当前请在电脑上继续
- 当前请在服务器环境中继续

---

## 6.5 设备切换提示页

### 页面目标

不要重点讲“控制权”，重点讲：

1. 工作已经切换位置
2. 用户现在该去哪继续
3. 另一台设备当前是什么状态

### 推荐标题

- 已切换到另一台设备

### 推荐正文

- 这次工作已经切到另一台设备继续
- 请在新的设备上继续，当前设备可查看，不可输入

### 推荐按钮

- 去这台设备继续
- 切回这里继续

---

## 6.6 成功提示草案

建议后续成功提示尽量短、明确、可执行。

推荐表达：

1. 已登录成功
2. 这台设备已添加
3. 已连接服务器环境
4. 已经在这台设备上打开
5. 已切到电脑继续
6. 已切到服务器继续

---

## 6.7 错误提示草案

建议后续错误提示遵循一个原则：

- 不只告诉用户错了什么
- 还要告诉用户下一步怎么做

推荐表达：

1. 这台设备还没有准备好，请先启动后再试
2. 没找到这次对话，请重新打开后再试
3. 当前没有访问这个环境的权限
4. 当前服务器还不支持这个功能，请更新后再试
5. 连接失败，请检查设备或服务器是否在线
6. 登录已失效，请重新登录后继续

### 7.13 页面文案草稿 v3

这一版不再只是“词语替换”或“低保真结构”，而是更接近真实页面的呈现方式。

目标只有三个：

1. 用户一眼看懂自己现在处于哪一步
2. 用户一眼看懂下一步最应该点什么
3. 页面语言尽量减少技术实现感

**页面目标**

- 让用户知道登录的目的不是“验证身份”本身，而是“登录后继续工作”

**推荐页面结构**

├──────────────────────────────────────┤
│ 邮箱地址                             │
│ [ name@example.com                ]  │
│                                      │
│ 密码或验证码                         │
│ [                                ]  │
│                                      │
│ [登录 helloVibe]                     │

#### A. 添加设备页

**页面目标**

- 让用户明白自己是在把一台电脑加入当前账号
- 让用户明白添加完成后能得到什么

**推荐标题**

- 添加设备

**设备类型区**

- 添加这台 Mac
- 添加这台 Windows 电脑

**说明文案**

- 添加后，这台设备会出现在你的设备列表中
- 之后你可以在这台设备上继续已有对话
- 如果这台设备还没有准备好，系统会提示下一步操作

**主按钮**

- 确认添加这台设备

**次按钮**

- 稍后再添加

**成功提示**

- 设备已添加成功
- 这台设备现在可以继续你的工作

**失败提示**

- 这台设备暂时无法添加，请稍后重试
- 这台设备还没有完成设置
- 当前账号无法添加这台设备

#### B. 连接服务器环境页

**页面目标**

- 让用户明白连接的是“服务器环境”，不是抽象技术节点
- 让用户明白连接后可以直接在云端继续工作

**推荐标题**

- 连接服务器环境

**推荐副标题**

- 把一个服务器环境接入当前账号，之后你可以直接在服务器上运行编码工具

**输入项标题**

- 服务器名称
- 服务器地址
- 连接方式

**辅助说明**

- 连接成功后，这个服务器环境会显示在首页和会话页中
- 你可以把它理解为一个可随时继续工作的云端位置

**主按钮**

- 连接服务器环境

**次按钮**

- 测试连接

**成功提示**

- 服务器环境已连接
- 现在你可以直接在服务器上开始或继续对话

**失败提示**

- 当前服务器环境不可用，请检查后重试
- 连接失败，请确认服务器地址和连接方式
- 当前账号暂时无法连接这个服务器环境

#### C. 成功提示总表

下面这些提示语尽量统一成“动作完成 + 用户下一步”的结构。

| 场景 | 推荐成功提示 |
| --- | --- |
| 登录成功 | 登录成功，欢迎回来 |
| 设备添加成功 | 设备已添加成功，现在可以在这台设备上继续工作 |
| 服务器连接成功 | 服务器环境已连接，现在可以直接在服务器上继续工作 |
| 工具选择成功 | 编码工具已准备好，可以开始新对话 |
| 新对话创建成功 | 新对话已创建，现在可以开始工作 |
| 切换设备成功 | 已切到这台设备继续 |
| 切换服务器成功 | 已切到服务器环境继续 |

#### D. 失败提示总表

失败提示尽量统一成“发生了什么 + 用户接下来怎么做”。

| 场景 | 推荐失败提示 |
| --- | --- |
| 登录失败 | 邮箱或密码不正确，请重新输入 |
| 验证码失效 | 验证码已过期，请重新获取 |
| 设备未就绪 | 这台设备还没有完成设置 |
| 没有设备 | 当前账号暂无可用设备，请先添加设备 |
| 服务器不可用 | 当前服务器环境不可用，请检查后重试 |
| 会话不存在 | 没找到这次对话，请返回首页重新选择 |
| 会话被占用 | 这次对话当前正在另一台设备上运行 |
| 工具不可用 | 当前编码工具暂时不可用，请稍后再试 |

#### E. 文案统一原则

为了让整个产品的语言更稳定，后续正式实现时建议继续遵守这几条：

1. 少说认证、执行端、agent、handoff 这类实现词
2. 多说账号、设备、服务器环境、编码工具、继续工作
3. 按钮尽量用动作词开头，比如添加、连接、开始、继续
4. 提示语尽量让用户知道“下一步应该做什么”
5. 同一个动作只保留一种主要叫法，不来回切换

## 10. 当前结论

本次结论如下：

1. 术语体系要从“技术实现语言”切到“用户任务语言”
2. 命名应从 Mac / terminal / Claude 视角，升级为设备 / 环境 / 工具视角
3. 页面草案要优先解决“用户现在到底在做什么”这个问题
4. 后续按钮、标题、提示语应尽量围绕“登录、添加设备、选择工具、继续工作”这条主线展开

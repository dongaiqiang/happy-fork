# 20260327 需求清单：Open in Mac（桌面接管）

## 1. 文档目的

本需求文档聚焦一个产品能力：  
手机端会话可在 Mac 本地 Claude Code 一键接管继续（Open in Mac）。

---

## 2. 业务背景

当前痛点：会话由手机端远程控制后，缺少“回到本地 Claude Code 继续同一会话”的明确产品能力。

---

## 3. 核心需求：Open in Mac / Open in Claude Code（桌面接管）

## 3.1 需求描述

当会话在手机端进行中时，用户希望可在 Mac 本地直接打开并接管同一会话，继续在本地 Claude Code 中工作，而非新建会话。

## 3.2 用户价值

1. 支持“移动端处理 + 桌面端深度开发”无缝切换  
2. 减少上下文丢失与重复输入  
3. 形成真实双端协同工作流

## 3.3 功能定义（产品语义）

新增动作：`Open in Mac` / `Open in Claude Code`

行为定义：

1. 在手机端会话详情页点击该动作  
2. 向目标机器下发“本地接管”请求  
3. 在 Mac 侧以 `claude --resume <claudeSessionId>` 打开对应会话  
4. 成功后会话控制权切回桌面端，手机端进入观察态或只读态
5. 不要求用户先手动“停止会话”；会话在线或有进行中任务时也可直接发起  
6. 切换过程由系统内部完成，用户只执行一次 Open in Mac

补充定义（双端协同）：

1. 同一会话支持手机端与 Mac 端同时可见，消息保持同步  
2. 任意时刻仅允许一端持有控制权（可输入、可执行操作）  
3. 另一端为观察态/只读态，不可发起写入或操作  
4. 提供“控制权切换开关”，支持手机端与 Mac 端双向切换主控
5. Open in Mac 默认应在 Mac 前台打开可见终端；无法前台打开时才降级后台并明确提示

## 3.4 前置条件

1. 目标机器在线  
2. daemon 正常运行  
3. 会话存在可恢复的 `claudeSessionId`  
4. 本地环境具备可执行 Claude Code 能力

## 3.5 验收标准

1. 手机端点击“Open in Mac”后，Mac 可打开同一会话并继续对话  
2. 新输入可继承既有上下文，非新开空会话  
3. 双端可同时看到同一会话内容，且消息同步一致  
4. 任意时刻仅有一端可控，另一端为只读观察态  
5. 控制权切换后新主控端可继续同一上下文  
6. 会话在线或任务进行中时，仍可直接点击 Open in Mac，无需用户先手动停止  
7. 失败场景有明确提示（离线、权限、会话不存在）

## 3.6 非目标（本期不做）

1. 不支持双端同时写入（并发输入）  
2. 不做多设备抢占策略细化  
3. 不做历史 UI 消息自动拼接迁移

## 3.7 守护进程关系与控制权模型

1. 守护进程定位为“本机执行代理”，负责会话拉起、恢复、停止与机器在线心跳上报  
2. 服务端定位为“控制权真相源”，负责记录当前控制方（mobile/mac）并做互斥校验  
3. 手机端与 Mac 端均可订阅同一会话消息流，实现双端同步可见  
4. 写入权限由服务端按控制方判定，非控制方仅允许只读观察与发起控制权切换  
5. 守护进程不独立做控制权仲裁，避免网络抖动导致双端同时可写

状态定义（会话级）：

1. `controller-mobile`：手机端可写，Mac 端只读  
2. `controller-mac`：Mac 端可写，手机端只读  
3. `switching`：控制权切换中，双端暂时禁止写入  
4. `offline-observe`：控制端离线，双方仅观察，等待恢复或重新切换

## 3.8 新建会话后显示 Claude 会话 ID（手机端可见）

1. 手机端发起“新建会话”后，宿主 Mac 启动 Claude 进程并生成 `claudeSessionId`  
2. `claudeSessionId` 写入会话 metadata，并通过现有同步链路回传到手机端  
3. 手机端会话详情页显示该 `claudeSessionId`，支持复制  
4. 若会话刚创建、ID 尚未回传，展示“正在获取 Claude 会话 ID”状态文案

## 3.9 Claude 原生能力边界（需按此做产品分层）

1. Claude CLI 原生支持 `--resume <claudeSessionId>` 恢复同一会话上下文  
2. Claude CLI 不负责 Happy App 与本地终端的双端状态同步，双端同步由 Happy 自身链路负责  
3. Claude CLI 不提供“手机端主控/终端主控”产品语义，主控切换由 Happy 服务端控制权模型负责  
4. 因此本需求采用“Claude 负责会话引擎，Happy 负责协同控制面”的分层

## 3.10 产品原则（最终语义）

1. 双端可见：手机端与 Mac 端始终可见同一会话信息  
2. 单端可控：任意时刻仅一个主控端可写入和执行  
3. 一键接管：`Open in Mac` 为单动作，不要求用户先手动停止会话  
4. 前台优先：Open in Mac 默认应在 Mac 端前台打开可见终端  
5. 可降级：前台打开失败时允许降级后台恢复，但必须明确提示当前模式  
6. 可回切：提供“主控开关”，支持 mobile ⇄ mac 双向切换

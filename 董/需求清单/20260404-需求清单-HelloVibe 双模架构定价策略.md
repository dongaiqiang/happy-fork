## 一、背景与目标

### 1.1 背景

HelloVibe 采用双模架构（本地专业版 + 云端托管版），两种模式的成本结构差异巨大：
- **模式 A（本地专业版）**：低成本（¥7-15/用户/月）
- **模式 B（云端托管版）**：高成本（¥95-280/用户/月）

需要设计合理的定价策略，既保证商业可持续性，又符合「让人通过氛围编程，轻松开发第一个程序」的产品愿景。

### 1.2 定价目标

| 目标 | 描述 | 衡量指标 |
|------|------|---------|
| **用户增长** | 降低门槛，快速获取用户 | 免费用户数、注册转化率 |
| **商业可持续** | 覆盖成本，实现盈利 | 毛利率 > 50%、LTV/CAC > 3 |
| **品牌定位** | 建立「氛围编程」第一品牌 | NPS 净推荐值、品牌提及率 |

### 12.2 用户分级额度建议

| 用户类型 | 日均使用场景 | 日均 tokens | 月均 tokens | 建议免费额度 |
|---------|-------------|------------|------------|-------------|
| **纯体验** | 每天问 2-3 个问题 | 5K | 15 万 | 10 万 ✅ |
| **学生轻度** | 每天写个小功能 | 20K | 60 万 | 50 万（学生版） |

| **专业开发者** | 全天使用 | 200K+ | 600 万+ | 专业版/团队版 |

### 12.3 额度限制「三刀流」设计

```
┌─────────────────────────────────────────────────────────┐
│  免费额度设计「三刀流」                                  │
├─────────────────────────────────────────────────────────┤
│  第一刀：日限额 —— 防止一天刷爆                          │
│  第二刀：月限额 —— 控制总成本                            │
│  第三刀：速率限制 —— 防止脚本滥用                        │
└─────────────────────────────────────────────────────────┘
```

**具体数值：**

| 套餐 | 日限额 | 月限额 | 速率限制 |
|------|--------|--------|---------|
| 免费版 | 5K tokens/天 | 10 万/月 | 10 请求/分钟 |
| 学生版 | 20K/天 | 50 万/月 | 30 请求/分钟 |
| 专业版 | 100K/天 | 200 万/月 | 100 请求/分钟 |
| 团队版 | 500K/天 | 1000 万/月 | 300 请求/分钟 |

**关键细节：**
- **日限额重置时间：** 凌晨 0 点（北京时间）
- **月限额重置时间：** 每月 1 号 0 点
- **超额处理：** 超额后可继续使用模式 A（本地），模式 B 暂停至次日/次月
- **提醒阈值：** 达到 50%、80%、100% 时分别推送通知

**超额计算公式：**
```
超额 tokens = max(0, 实际使用 - 套餐额度)
超额费用 = 超额 tokens × ¥0.02/1K
```

## 十四、付费墙（Paywall）设计

### 14.1 付费墙出现时机

| 时机 | 触发条件 | 转化率 | 推荐度 |
|------|---------|--------|--------|
| **注册后立刻** | 新用户首次进入 | 低（1-3%） | ❌ 不推荐 |
| **首次使用时** | 第一次发送消息后 | 中（5-8%） | ⚠️ 一般 |
| **额度用尽时** | 免费 tokens 用完 | 高（15-25%） | ✅ 推荐 |
| **高价值时刻** | 完成一个任务后 | 最高（20-30%） | ✅✅ 强烈推荐 |
| **功能限制时** | 想用模式 B 但被限 | 中（10-15%） | ✅ 推荐 |

### 14.2 付费墙设计原则

```
┌─────────────────────────────────────────────────────────┐
│  付费墙设计「五步法」                                    │
├─────────────────────────────────────────────────────────┤
│  1. 先给甜头 —— 让用户体验价值                           │
│  2. 适时出现 —— 在「啊哈时刻」后弹出                     │
│  3. 对比强烈 —— 免费 vs 付费价值差异明显                 │
│  4. 降低门槛 —— 首月优惠/分期降低决策难度                │
│  5. 限时紧迫 —— 24 小时限时优惠促决策                    │
└─────────────────────────────────────────────────────────┘
```

# 20260406 429 返回格式统一与接口验证记录

## 1. 本轮目标

- 统一 quota 场景与 validity 场景的 `429` 返回格式
- 明确 App 如何稳定消费
- 给主线留下可复核的接口验证记录

## 2. 统一后的接口合同

### 2.1 顶层结构

所有本轮主线 `429` 统一为以下顶层字段：

```json
{
  "error": "quota_limit_exceeded | validity_check_failed",
  "reason": "具体原因枚举",
  "message": "前端可直接展示的文案",
  "upgradeUrl": "/pricing"
}
```

### 2.2 quota 场景

#### 日额度不足

```json
{
  "error": "quota_limit_exceeded",
  "reason": "daily_limit_exceeded",
  "message": "今日额度不足，请升级后继续发送消息",
  "upgradeUrl": "/pricing",
  "estimated": 123,
  "remaining": 0,
  "dailyLimit": 5000,
  "dailyUsed": 5000
}
```

#### 月额度不足

```json
{
  "error": "quota_limit_exceeded",
  "reason": "monthly_limit_exceeded",
  "message": "本月额度不足，请升级后继续发送消息",
  "upgradeUrl": "/pricing",
  "estimated": 123,
  "remaining": 0,
  "monthlyLimit": 100000,
  "monthlyUsed": 100000
}
```

### 2.3 validity 场景

#### 试用期过期

```json
{
  "error": "validity_check_failed",
  "reason": "trial_expired",
  "message": "7 天试用已到期，请升级后继续发送消息",
  "upgradeUrl": "/pricing",
  "expiresAt": "2026-04-06T10:00:00.000Z"
}
```

#### 订阅未激活 / 已过期

```json
{
  "error": "validity_check_failed",
  "reason": "subscription_inactive | subscription_expired",
  "message": "当前订阅未激活，请升级或恢复订阅后继续发送消息",
  "upgradeUrl": "/pricing",
  "expiresAt": "2026-04-06T10:00:00.000Z"
}
```

## 3. 前端可消费方式

### 3.1 当前主线策略

- 先看 HTTP 状态码是否为 `429`
- 再看 `error` 是否属于：
  - `quota_limit_exceeded`
  - `validity_check_failed`
- 再看 `reason` 做分支判断：
  - `daily_limit_exceeded`
  - `monthly_limit_exceeded`
  - `trial_expired`
  - `subscription_inactive`
  - `subscription_expired`
- 文案直接优先展示 `message`

### 3.2 本轮已落地消费点

- `/Users/dongaiqiang/Documents/mycode/codes/00-chanpin/hellovibe-main/packages/happy-app/sources/sync/messageSendFailure.ts`
  - 统一归一化 `429` 失败载荷
  - 对已知 quota / validity `429` 直接标记为 `shouldStopRetry: true`
- `/Users/dongaiqiang/Documents/mycode/codes/00-chanpin/hellovibe-main/packages/happy-app/sources/sync/sync.ts`
  - 收到已知 `429` 后停止 backoff 重试
  - 直接把 `message` 写成会话事件消息

### 3.3 当前明确不再做的旧行为

- 不再靠字符串匹配 `insufficient_quota`
- 不再把这类 `429` 当作普通网络错误一直重试
- 不再让 App 只能在 30 秒 watchdog 超时后才给出一个笼统失败提示

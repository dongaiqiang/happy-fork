# 20260406 主线联调与验证记录

## 1. 验证范围

本轮验证对象仅覆盖以下主线改动：

- `429` 接口合同统一
- 消息发送链路的 validity + quota 主线门禁
- App 对统一 `429` 的消费方式
- quota 路由重新接回主 API

## 2. 验证方式

本轮采用接口等价验证，不以真机为必要前置。原因：

- 本轮改动集中在后端接口合同与 App 的失败处理逻辑
- 风险主要在：
  - 返回格式是否统一
  - 失败分支是否正确
  - App 是否停止错误重试
  - 构建与类型是否稳定
- 这些风险通过路由测试、前端单测、server build、app typecheck 已能直接覆盖

## 4. 联调结论

### 4.1 服务端结论

- `POST /v3/sessions/:sessionId/messages` 已具备统一的主线拒绝格式
- validity 与 quota 场景都返回稳定的 `error + reason + message`
- quota 表不再静默缺失放行

### 4.2 前端结论

- App 已能识别主线 `429`
- 已知 quota / validity `429` 会停止无限重试
- 服务端 `message` 会被直接转成会话事件消息，用户能看到明确失败原因

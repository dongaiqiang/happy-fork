## 3. 上线后验证

### 3.0 手机端入口先确认

阿里云这次部署完成后，手机端要先分清自己打开的是哪一种入口：

- 如果手机里看到的是 Happy 登录页或会话页，就继续往下做联调
- 如果手机里看到的是 `No development servers found` / `Enter URL manually`，说明你现在回到了 Expo Development Build 容器，不是阿里云部署后的业务页面

当前这轮阿里云联调，推荐直接用手机浏览器打开：

```text
https://app.easycode-ai.xyz
```

然后在手机页面的服务器设置里，把服务端地址改成：

```text
https://api.easycode-ai.xyz
```

补充说明：

- `app.easycode-ai.xyz` 是手机浏览器打开的前端地址
- `api.easycode-ai.xyz` 是手机 App / 手机浏览器里要配置的服务端地址
- Expo Development Build 里 `Enter URL manually` 要填的是本地 Expo 开发服务地址，例如 `http://你的Mac局域网IP:8081`，不是这次阿里云部署验证要走的入口
- 如果你刚才在手机里点了注销，最稳的恢复方式就是直接回到手机浏览器访问 `https://app.easycode-ai.xyz`

### 3.0A 手机浏览器实际操作步骤

如果你现在手机上看到的就是 `https://app.easycode-ai.xyz` 这个欢迎页，按下面顺序做：

```text
1. 用 Safari 打开 https://app.easycode-ai.xyz
2. 先不要点“使用移动应用登录”或“创建账户”，先点右上角的服务器图标
3. 进入“服务器配置”页面后，在自定义服务器 URL 里填 https://api.easycode-ai.xyz
4. 点“保存”，等页面校验通过
5. 返回首页，再根据你的目标选择下面两种登录方式
```

如果你是要恢复原来那个账号，而不是新建一个空账号：

```text
1. 点“使用移动应用登录”
2. 进入二维码页面后：
   - 如果你手里还有另一台已经登录 Happy 的手机/设备，就用它扫码
   - 如果你手里保存过原账号的 secret key，就点“Restore with Secret Key Instead”后粘贴 key
3. 恢复成功后回到会话列表
```

如果你只是想先进入系统做联调，不要求保留旧账号数据：

```text
1. 直接点“创建账户”
2. 创建成功后进入会话页
3. 再继续后面的 Open in Mac 联调
```

这几个按钮的含义要分清：

- `使用移动应用登录`：用于恢复已有账号，推荐在你要找回原来的会话时使用
- `创建账户`：用于新建一个全新的浏览器账号，不会自动带回你原来的历史会话
- 右上角服务器图标：用于把手机浏览器当前连接的服务端改成 `https://api.easycode-ai.xyz`

如果你现在只有这一台手机，而且原生 Happy App 已经注销、也没有保存过 secret key，那手机浏览器里就没法直接恢复旧账号；这种情况下只能：

- 先想办法重新拿到原账号的 secret key
- 或者在另一台已登录设备上扫码恢复
- 或者先新建一个浏览器账号继续做联调

### 3.0B 手机浏览器、原生 App、Mac 终端三者关系

这三个东西不是一回事，职责要分开看：

```text
1. 手机浏览器（https://app.easycode-ai.xyz）
   - 它是阿里云上的前端页面
   - 用来登录账号、看会话、点 Open in Mac
   - 右上角服务器图标里配置的是它要连哪个 API

2. 原生 Happy App / Expo Dev Client
   - 它是手机上的原生容器
   - 只有在“扫码恢复账号”或“本地 Expo 开发”时才一定会用到
   - 当前这轮阿里云联调，不是必须先打开它

3. Mac 终端里的 happy auth login / daemon
   - 它是本地执行端
   - 用来把你的 Mac 机器注册到同一个 Happy 账号下
   - 只有 Mac daemon 在线，手机里的 Open in Mac 才能找到这台机器
```

最容易混淆的是这两件事：

- 手机浏览器里的 `创建账户`，是在“给手机浏览器自己创建一个账号”
- Mac 终端里的 `auth login`，是在“把这台 Mac 机器绑定到某个已经存在的账号”

所以正确顺序是：

```text
A. 先让手机浏览器登录进一个账号
B. 再让 Mac 终端登录到同一个账号
C. 然后手机里点 Open in Mac，把会话切到这台 Mac
```

### 3.0C 终端里那个认证界面该怎么选

如果你在 Mac 终端里执行了：

```bash
node packages/happy-cli/scripts/env-wrapper.cjs stable auth login
```

终端会问：

```text
1. Mobile App
2. Web Browser
```

这两个选项的意思分别是：

- `Mobile App`：让一台已经登录 Happy 的移动端设备来扫码批准这次终端登录
- `Web Browser`：直接在浏览器里完成这次终端登录

你当前这轮阿里云联调，推荐直接选：

```text
2. Web Browser
```

原因很简单：

- 你现在手机端还在梳理账号状态
- 手机浏览器和原生 App 容易混
- 终端选 `Web Browser` 最直接，会在浏览器里打开 `app.easycode-ai.xyz/terminal/connect...`

你可以把它理解成：

```text
手机浏览器首页的“创建账户/使用移动应用登录”
    是在处理“手机这边是谁”

Mac 终端里 auth login 选 Web Browser
    是在处理“这台 Mac 归谁”
```

### 3.0D 术语优化需求

这轮联调里已经确认，当前产品里的不少术语对普通用户不够直白，容易把“账号登录”“设备绑定”“会话切换”混在一起。这个问题已经记录，后续要单独收敛成一轮文案优化。

当前暴露最明显的几组术语是：

```text
1. “连接终端”
   用户真实理解更接近：
   “让这台 Mac 加入当前账号”

2. “接受连接”
   用户真实理解更接近：
   “同意这台 Mac 登录”

3. “创建账户”
   用户真实理解更接近：
   “新建一个浏览器账号”

4. “使用移动应用登录”
   用户真实理解更接近：
   “用已登录设备恢复原账号”

5. “Open in Mac”
   用户真实理解更接近：
   “把当前会话切到 Mac 继续”
```

后续文案优化的目标不是“更专业”，而是：

- 用户第一次看就知道这一步是在登录账号、绑定设备，还是切换会话
- 用户不需要理解“认证、公钥、终端请求”这些技术词，也能完成操作
- 同一件事在手机浏览器、原生 App、Mac 终端里尽量使用同一套叫法

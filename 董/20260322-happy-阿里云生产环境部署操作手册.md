# Happy 生产环境部署操作手册（阿里云篇）【更新版】
本手册旨在指导你如何在阿里云服务器上，使用真实域名和 HTTPS 证书，部署 Happy 的“云端分离”架构。
部署完成后，你可以在任何地方通过手机/浏览器安全地控制你本地电脑（MacBook）进行编程。

## 架构说明
阿里云（云端信令）：负责运行 Web UI 和 Server（鉴权与消息路由），并使用 Caddy 处理 HTTPS 证书。
本地 MacBook（计算节点）：负责运行 Daemon，通过合法的 WSS 长连接挂载到阿里云，实际执行代码。
手机/外部设备：通过域名访问阿里云上的 Web UI。

## 第一阶段：阿里云前期准备
### 1. 准备域名
购买一个域名（例如 easycode-ai.xyz）。
注意：如果阿里云服务器在中国大陆节点（如杭州、北京），域名必须完成 ICP 备案。如果是香港或海外节点则不需要。

进入阿里云 云解析 DNS 控制台。
添加两条 A 记录，指向你阿里云服务器的公网 IP：
- 主机记录：app （用于 Web 界面，完整域名为 app.easycode-ai.xyz）
- 主机记录：api （用于 Server 通信，完整域名为 api.easycode-ai.xyz）

### 2. 开放服务器端口
进入阿里云 ECS 控制台 -> 安全组规则 -> 入方向，添加规则放行以下端口：
- 80 (TCP) - 用于 Caddy 自动申请 Let's Encrypt 证书
- 443 (TCP) - 用于 HTTPS 访问
- 22 (TCP) - SSH 登录（通常已默认开放）
- 8081 (TCP) - [新增] Happy App 前端服务端口（可选，仅用于调试）

## 第二阶段：阿里云服务器部署
使用 SSH 登录到你的阿里云服务器。

### 1. 安装基础环境 (Node.js & Yarn & PM2)
根据你的服务器操作系统类型，选择对应的安装命令：

#### 选项 A: 如果是 Ubuntu / Debian 系统
```bash
# 安装 Node.js 22.x (Happy 推荐版本)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
```

#### 选项 B: 如果是 Alibaba Cloud Linux / CentOS / RHEL 系统
```bash
# 安装 Node.js 22.x
curl -fsSL https://rpm.nodesource.com/setup_22.x | sudo bash -
sudo yum install -y nodejs
```

#### 全局安装 yarn 和 pm2 (通用)
(注意：请确保 Node.js 安装完成后，再单独执行以下命令，避免复制粘贴时命令粘连报错)
```bash
sudo npm install -g yarn pm2
```

### 2. 安装并配置 Caddy
Caddy 是一个极简的反向代理，它会自动为你申请和续期 HTTPS 证书。

#### 选项 A: 如果是 Ubuntu / Debian 系统
```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install caddy
```

#### 选项 B: 如果是 Alibaba Cloud Linux / CentOS / RHEL 系统
```bash
sudo yum install -y yum-plugin-copr
sudo yum copr enable @caddy/caddy -y
sudo yum install -y caddy
```

#### 编辑 Caddy 配置文件 (使用 vi)：
```bash
sudo vi /etc/caddy/Caddyfile
```
清空里面的内容，粘贴以下配置（请把域名换成你自己的）：
```caddyfile
app.easycode-ai.xyz {
    # 托管静态编译后的 Web UI 文件
    root * /home/admin/.openclaw/workspace/happy/packages/happy-app/dist
    file_server
    try_files {path} /index.html
}

api.easycode-ai.xyz {
    reverse_proxy localhost:3005
}
```
保存后重启 Caddy：
```bash
sudo systemctl restart caddy
```

### 3. 部署 Happy 代码
```bash
# 找个目录克隆代码
cd /home/admin/.openclaw/workspace/happy/

# 安装依赖
yarn install
```

### 4. 编译并导出前端静态文件
在阿里云等生产环境，不建议使用占用内存极大的开发服务器 (`expo start`)，而是应该导出静态文件交由 Caddy 直接托管。

## 避坑指南（血泪经验，必看！）

### 1. 内存不足导致的构建失败 (OOM)
阿里云 4G 内存服务器如果在运行 `expo start` 或 `expo export` 时被 `SIGKILL` 杀死，是因为 Node.js 内存溢出。
**解决方案**：不要在服务器上打包！在本地 Mac 上打包好，将 `dist` 目录上传到服务器，然后用 Caddy 进行纯静态代理。

### 2. Caddy 403 Forbidden 权限问题
如果把静态文件放在 `/home/admin/` 目录下，Caddy 无论怎么配置都会报 403。这是因为 Linux/CentOS 的严格家目录权限和 SELinux 策略导致的。
**解决方案**：永远把 Web 静态文件放在标准的 `/var/www/` 目录下，并赋予 `www-data` 或 `caddy` 权限。

### 3. PGLite 数据库兼容性与锁死问题
官方虽然支持 PGLite（内嵌 Postgres），但在 CentOS/Alibaba Linux 下极易出现 Prisma C 扩展找不到表、`DATABASE_URL` 解析报错、以及 `migration_lock.toml` 引擎冲突的问题。
**解决方案**：在生产环境**直接放弃 PGLite**，通过 `yum` 安装原生 PostgreSQL，并使用 `prisma db push` 暴力同步表结构，最稳妥。

### 4. PM2 解析 yarn 报错 (Bash 语法错误)
如果在 PM2 的 `ecosystem.config.js` 里直接把 `script` 写成 `yarn`，在某些 Linux 下 PM2 会错误地用 bash 解释器去执行 JS 文件，导致满屏的 `use strict: command not found`。
**解决方案**：写一个纯正的 `.sh` 脚本（如 `start-server.sh`），在里面设置环境变量并 `exec yarn ...`，然后让 PM2 跑这个 sh 脚本。

### 5. 加密模式与“幽灵 Token”连接失败
如果你在折腾过程中**重装过数据库/清空过服务器数据**，会导致本地电脑和浏览器的加密 Key 成为“幽灵 Token”。
如果你在终端连接 Web 时提示**“连接终端失败”**，通常有以下原因：
- **浏览器缓存不匹配**：网页端保存的私钥与新数据库不匹配。解决：在浏览器开发者工具里清空 LocalStorage。
- **Mac 终端缓存不匹配**：CLI 保存的旧授权已被服务器清空。解决：执行 `rm -rf ~/.happy/*` 删掉本地状态后重新 login。
- **浏览器 Web Crypto API 限制**：**千万不要用 Safari！** Safari 对跨域/特定协议下的加密 API 限制极严，会导致前端直接解密失败。**强烈建议全程使用 Chrome 或 Edge 浏览器**。

### 6. 环境变量不同步
如果后端开启了 `ENABLE_PLAINTEXT_MODE=true`（明文模式），则前端打包时、Mac 终端登录时，**必须**全部带上这个变量，否则一边加密一边明文，瞬间报错。
**建议**：既然已经配好了 HTTPS 域名，**直接删除所有的明文变量**，全链路采用官方默认的端到端加密模式，省去所有同步烦恼！

### 5. 初始化数据库与启动 API Server
Happy Server 官方架构强制要求使用 **PostgreSQL** 数据库。
由于 PGLite（内嵌版 Postgres）在某些 Linux 发行版下的 Prisma C 扩展兼容性问题会导致频繁报错，**我们强烈建议直接安装并使用原生的 PostgreSQL 数据库**。

#### 第一步：安装并配置原生 PostgreSQL
在阿里云服务器上执行以下命令安装 Postgres：
```bash
# 1. 安装 PostgreSQL
sudo yum install -y postgresql-server postgresql-contrib

# 2. 初始化数据库集群
sudo postgresql-setup initdb

# 3. 启动并设置开机自启
sudo systemctl start postgresql
sudo systemctl enable postgresql

# 4. 配置本地免密登录 (针对 root/admin 切换 postgres 用户)
sudo sed -i 's/ident/trust/g' /var/lib/pgsql/data/pg_hba.conf
sudo sed -i 's/peer/trust/g' /var/lib/pgsql/data/pg_hba.conf
sudo sed -i 's/md5/trust/g' /var/lib/pgsql/data/pg_hba.conf
sudo systemctl restart postgresql

# 5. 切换到 root 用户并创建 happy 数据库
sudo su - root -c "psql -U postgres -c \"CREATE USER happy WITH PASSWORD 'happy2026';\""
sudo su - root -c "psql -U postgres -c \"CREATE DATABASE happy_db OWNER happy;\""
```

#### 第二步：初始化数据库表结构
回到项目根目录，通过标准的 `DATABASE_URL` 让 Prisma 自动建表：
```bash
cd /home/admin/.openclaw/workspace/happy/

# 确保 Prisma 客户端和 schema 一致
yarn workspace happy-server generate

# 执行数据库建表 (注意这里用 db push 避免受到本地旧环境 sqlite lock 的干扰)
DATABASE_URL="postgresql://happy:happy2026@localhost:5432/happy_db" yarn workspace happy-server prisma db push
```

#### 第三步：安装并启动 Redis

如果后端环境变量里配置了 `REDIS_URL=redis://127.0.0.1:6379`，Redis 也必须先准备好；否则 `happy-api` 会在启动时直接退出，表现为 PM2 不断重启、接口域名返回 502。

```bash
sudo yum install -y redis || (sudo apt-get update && sudo apt-get install -y redis-server)
sudo systemctl enable redis || sudo systemctl enable redis-server
sudo systemctl restart redis || sudo systemctl restart redis-server
redis-cli -h 127.0.0.1 -p 6379 ping
```

#### 第四步：使用 PM2 后台启动 Server
创建一个干净的 Shell 脚本来启动服务，避免 PM2 解析错误：

```bash
# 创建 start-server.sh 启动脚本
cat << 'EOF' > start-server.sh
#!/bin/bash
cd /home/admin/.openclaw/workspace/happy/

# 基础配置
export DATA_DIR="./data"
export METRICS_ENABLED="false"
export ENABLE_PLAINTEXT_MODE="true"
export HANDY_MASTER_SECRET="happy-master-secret-2026"

# 填入真实的 Postgres 连接地址
export DATABASE_URL="postgresql://happy:happy2026@localhost:5432/happy_db"
export REDIS_URL="redis://127.0.0.1:6379"

# 启动普通模式的 server (不使用 standalone)
exec yarn workspace happy-server start
EOF

# 赋予执行权限
chmod +x start-server.sh

# 杀掉之前所有的错误进程
pm2 delete all
pm2 cleardump

# 使用 PM2 挂载新脚本
pm2 start ./start-server.sh --name happy-api

# 保存 pm2 状态
pm2 save
```

### 5. [可选] 在阿里云上部署 Daemon (将服务器变成云端开发机)
你可以让阿里云服务器不仅仅作为“邮局”，同时也作为一台可以执行代码的计算节点。这样你出门时，连家里的 MacBook 都不用开，直接在手机上控制阿里云写代码。

在阿里云终端执行：
```bash
# 1. 登录云端 Server
HAPPY_SERVER_URL=https://api.easycode-ai.xyz yarn workspace happy-coder cli auth login

# 2. 验证后，使用 PM2 守护启动 Daemon
HAPPY_SERVER_URL=https://api.easycode-ai.xyz pm2 start "yarn workspace happy-coder cli daemon start-sync" --name "happy-daemon"
pm2 save
```
完成这一步后，你的手机 Web 端会出现一张名为 Aliyun-Ubuntu (或你的服务器主机名) 的卡片。

## 附录：关于端到端加密 (E2EE) 与明文模式的特别说明
在部署步骤的第 4 步中，我们使用了 ENABLE_PLAINTEXT_MODE=true 等环境变量来禁用了应用层的端到端加密。这里详细解释一下背后的原因以及与官方部署的区别。

### 1. 为什么官方部署必须开启端到端加密？
在 Happy Coder 官方提供的公共 SaaS 服务中，全球的开发者都在连接同一个 Server。基于零信任架构 (Zero-Trust Architecture)：
- 用户不应该信任公共服务器的拥有者（如果服务器被黑客攻破，代码和本地权限就会暴露）。
- 因此，官方架构会在 Web UI（手机端）和 Daemon（电脑端）分别生成公私钥。
- 所有消息在发送前，都在手机端使用电脑端的公钥进行加密（基于 libsodium / TweetNaCl）。
- 官方中转 Server 收到的只是一堆 Base64 乱码，它只负责转发，没有私钥，根本无法解密看到里面的内容。这保证了绝对的隐私。

### 2. 为什么我们要在阿里云私有化部署中禁用它？
当我们在一台自己购买的阿里云服务器上进行私有化部署时，信任模型发生了改变：
- 你是服务器的主人：中转 Server 完全在你的控制之下，你不需要防范“服务器拥有者偷看你的数据”。
- 外部 HTTPS 已提供足够安全：我们在步骤 2 中配置了 Caddy 反向代理并绑定了域名，自动启用了标准的 Let's Encrypt HTTPS (TLS) 证书。这意味着从手机到阿里云的网络传输链路已经被加密保护，黑客无法在公共网络上窃听。
- 极大的降低运维与调试成本：如果开启端到端加密，所有的 WebSocket 消息在日志里都是 Base64 乱码。一旦系统出现“卡死”或指令不执行的 Bug，你将无法通过日志排查问题。开启明文模式后，网络请求和日志中都是清晰的 JSON 结构，极大地方便了后期的维护。
- 降低性能开销：去除了应用层的二次加解密过程，可以减少 ECS 实例不必要的 CPU 消耗。

### 总结：
在自己掌控的、且已经配置了标准 HTTPS 证书的私有化云服务器上，通过注入 ENABLE_PLAINTEXT_MODE=true 禁用应用层的端到端加密，是在保证安全的前提下，换取更好的性能和极佳的可维护性的一种合理权衡。

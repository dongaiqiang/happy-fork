## 二、 部署架构与环境配置 (环境变量)

我们没有硬编码修改服务端的逻辑，而是通过注入环境变量（这些变量不提交到 Git）来改变其行为。
在阿里云服务器和本地 Mac 上，我们依赖以下变量：

*   **`HAPPY_SERVER_URL`**: 本地 Daemon 启动时，强制指向 `https://api.easycode-ai.xyz`，使其脱离本地开发环境，接入生产云端。
*   **`EXPO_PUBLIC_HAPPY_SERVER_URL` / `EXPO_PUBLIC_SERVER_URL`**: 网页端打包时，强制其默认 API 请求指向生产云端。
*   **数据库切换**: 放弃了官方默认且不稳定的嵌入式 `PGLite`，通过 `DATABASE_URL` 环境变量强行对接了阿里云本地的原生 `PostgreSQL`。

## 四、 历史会话接续生成（Resume）能力适配

本次新增了“已结束历史会话可接续生成”的能力，对应 Cloud Code 的 `--resume` 语义。
如果后续与上游合并出现冲突，请保留以下定制逻辑。

### 1. App 侧：spawn 参数支持透传历史会话 ID

**文件路径**: `packages/happy-app/sources/sync/ops.ts`

*   **新增点**:
    *   `SpawnSessionOptions` 增加 `sessionId?: string` 字段；
    *   `machineSpawnNewSession(...)` 调用 machine RPC 时，透传 `sessionId` 到 `spawn-happy-session` 请求体。
*   **目的**:
    *   让移动端能够明确告诉 daemon：这次不是新会话，而是恢复某个历史会话上下文。

### 2. CLI Daemon：真正消费 sessionId 并注入 --resume

**文件路径**: `packages/happy-cli/src/daemon/run.ts`

*   **新增点**:
    *   在 `spawnSession(...)` 内解析 `resumeSessionId`；
    *   tmux 启动命令在有 `resumeSessionId` 时追加 `--resume <id>`；
    *   常规进程启动参数在有 `resumeSessionId` 时也追加 `--resume <id>`；
    *   增加保护：当前仅允许 `claude` agent 使用 resume，其他 agent 返回明确错误。
*   **目的**:
    *   让 daemon 不再忽略前端传入的会话 ID，真正触发 Claude 历史上下文恢复。

### 3. App 会话详情页：新增 Resume Session 入口

**文件路径**: `packages/happy-app/sources/app/(app)/session/[id]/info.tsx`

*   **新增点**:
    *   在“Quick Actions”中新增 `Resume Session`；
    *   增加 `resumeSession(...)` 流程：校验 `machineId/path/claudeSessionId`、检查机器在线、调用 `machineSpawnNewSession`、处理目录不存在确认弹窗；
    *   仅在满足条件时展示入口：会话已结束、可定位机器与路径、存在 `claudeSessionId`、且 flavor 为 `claude`。
*   **目的**:
    *   用户在历史会话详情页可一键接续，而不是必须手动新建。

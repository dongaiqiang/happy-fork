## 2. 最常用命令（先看这个）

### 2.1 安装依赖

- 命令：`yarn install`
- 在哪跑：仓库根目录
- 作用：安装/刷新 monorepo 全部依赖，应用 workspace/nohoist 规则。
- 什么时候用：
  - 首次拉代码后
  - 修改 `package.json` 后
  - 出现奇怪模块报错时（尤其是 monorepo 依赖定位问题）

### 2.2 启动后端

- 命令：`yarn dev`
- 在哪跑：`packages/happy-server`
- 作用：启动 API/Socket 服务（ASR 流式转写依赖它）。
- 什么时候用：
  - 调试 App 聊天、语音转文字
  - 需要看 server 日志（`[ASR]`、鉴权、消息写入等）

### 2.3 启动前端 Bundler（Dev Client）

- 命令：`npx expo start --dev-client -c`
- 在哪跑：`packages/happy-app`
- 作用：启动 Metro，`-c` 清缓存，给真机 Dev Client 提供 JS 包。
- 什么时候用：
  - 日常开发必开
  - 改动后出现“旧代码还在跑”时

### 2.4 真机安装/重装 iOS 客户端

- 命令：`npx expo run:ios --device --no-install`
- 在哪跑：`packages/happy-app`
- 作用：构建并安装 iOS App 到真机（不会重新安装 npm 依赖）。
- 什么时候用：
  - 改了原生层（pods、插件、iOS 工程）后
  - App 打不开或需要重新部署到手机

## 3. iOS 相关命令

### 3.1 Pod 安装

- 命令：`pod install`
- 在哪跑：`packages/happy-app/ios`
- 作用：同步 iOS Pods 依赖。
- 什么时候用：
  - 改了 Expo 插件/原生模块/Podfile 后
  - iOS 构建提示缺 pod 时

### 3.2 仅做 iOS 编译校验（不启动 App）

- 命令：`xcodebuild -workspace easycodedev.xcworkspace -scheme easycodedev -configuration Debug -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build`
- 在哪跑：`packages/happy-app/ios`
- 作用：纯编译检查，快速判断 native 编译是否通过。
- 什么时候用：
  - CI前自检
  - 定位“是 JS 问题还是 iOS 编译问题”

### 3.3 预构建（重新生成 ios/android 工程）

- 命令：`npx expo prebuild --platform ios --no-install`
- 在哪跑：`packages/happy-app`
- 作用：根据 `app.config.js` 和插件重新生成原生工程。
- 什么时候用：
  - Expo 插件配置变更后
  - 原生工程状态异常需要“重建壳子”

## 4. 质量检查命令

### 4.1 App 类型检查

- 命令：`yarn typecheck`
- 在哪跑：`packages/happy-app`
- 作用：执行 TypeScript 类型检查。

### 4.2 Server 构建检查

- 命令：`yarn build`
- 在哪跑：`packages/happy-server`
- 作用：编译 server（通常用于确认 TS/构建链路正常）。

## 5. 推荐调试流程（你现在用这个）

按顺序开 2~3 个终端：

1) 根目录跑：`yarn install`  
2) `packages/happy-server` 跑：`yarn dev`  
3) `packages/happy-app` 跑：`npx expo start --dev-client -c`  
4) 如需重装 iOS：`npx expo run:ios --device --no-install`

语音转文字测试时，重点看：

- 前端日志：`[ASR Frontend] 收到后端发来的 asr_text ...`
- 后端日志：`[ASR] 讯飞返回 (sn..., pgs...) ...`

## 6. 常见误区

- `yarn dev` 不是在根目录跑，而是在 `packages/happy-server` 跑。
- `expo start` 只启动前端 bundler，不会自动启动后端。
- 改了原生配置只跑 `expo start` 不够，通常要补一次 `expo run:ios`。
- 出现诡异缓存问题时，优先用 `npx expo start --dev-client -c`。
